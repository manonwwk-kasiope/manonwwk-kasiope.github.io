# Recette iOS depuis l’écran d’accueil

La cible XCTest utilise le Safari du simulateur, SpringBoard et Web.app. Le serveur de test ouvre un port libre sur 127.0.0.1. Chaque exécution utilise un nom unique au format S2985QA suivi de quatre chiffres hexadécimaux. Le serveur garde le manifeste de la distribution, y compris son start_url, et remplace uniquement ses deux noms pour identifier le raccourci. Le serveur injecte ?muet=1 dans l’historique du document avant tout script lorsqu’iOS ouvre le start_url sans paramètre. La réponse HTML directe permet son emploi depuis le service worker. La garde bloque les API de lecture et de synthèse avant le bundle. Le serveur refuse les fichiers audio.

1. Copier ce dossier dans un dossier temporaire, exécuter xcodegen generate puis xcodebuild -scheme AccueilArcadeTests -destination 'generic/platform=iOS Simulator' -derivedDataPath build build-for-testing CODE_SIGNING_ALLOWED=NO. Cette étape fonctionne simulateur arrêté.
2. Depuis le dossier source, exécuter servir.py avec le chemin de la distribution de recette et le nom QA. Conserver la sortie dans un journal. Appeler preparer.py avec le répertoire build, l’URL locale exacte de la première ligne et le même nom QA.
3. Au créneau exclusif, exécuter test-without-building avec le fichier AccueilQA.xctestrun, -parallel-testing-enabled NO, -resultBundlePath et l’identifiant explicite du simulateur dédié. Le test ouvre Safari normalement, vérifie la préparation, ajoute le raccourci depuis Partager, lance son icône, joue en silence puis ouvre la pause. Le nettoyage cible l’icône portant exactement le nom QA contrôlé avant création.
4. Utiliser verifier.py sur le journal serveur. Conserver l’état du premier chargement autonome et les tailles réelles de l’écran, du viewport et de l’arène. La réussite du parcours Safari ordinaire reste indépendante. Arrêter le serveur temporaire et le simulateur dédié après contrôle de la disparition du raccourci.
